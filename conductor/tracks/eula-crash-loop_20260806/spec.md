# Specification: Fix EULA Crash Loop — Window Animation Bug and Bundle Path Mismatch

**Track ID:** eula-crash-loop_20260806
**Type:** Bug
**Created:** 2026-08-06
**Status:** Draft

## Summary

Fix two first-run bugs discovered during a 5-agent team-debug investigation:

1. **Window animation fight (Bug 1):** The `FirstRunWindowConfigurator` uses `NSRect(origin: .zero, …)` in the `default` case, causing the EULA/Setup window to slide to the bottom-left corner of the screen before bouncing back to center. The fix pattern already exists in the `.ready` case of the same method.

2. **Bundle path mismatch (Bug 2):** `bundle-app.sh` copies `Syxx_SyxxApp.bundle` to `Syxx.app/Contents/Resources/`, but SwiftPM's generated `Bundle.module` looks for it at `Syxx.app/Syxx_SyxxApp.bundle` (the `.app` root). The build-time fallback path hardcoded in `resource_bundle_accessor.swift` silently masks this on dev machines. On user machines, it causes a `fatalError` crash on launch.

## Context

Syxx's macOS app uses a first-run onboarding flow with three states: `.agreementRequired` (EULA), `.setupRequired` (Guided Setup), and `.ready` (main dashboard). The `FirstRunWindowConfigurator` manages the window chrome and sizing for each state. During first-run states, the window is borderless and sized to the current card. When setup completes, the window transitions to standard chrome at 1040×613.

The `Syxx_SyxxApp.bundle` is a SwiftPM resource bundle containing fonts, icons, and other assets. `Bundle.module` (auto-generated by SwiftPM) resolves the bundle at runtime. If the bundle cannot be found, the app crashes immediately.

## Acceptance Criteria

### Bug 1 — Window animation

- [ ] **AC-1.1:** The `default` case in `FirstRunWindowConfigurator.configure()` uses `window.frame.origin` (preserving the current position) instead of `origin: .zero` when resizing the window during state transitions.
- [ ] **AC-1.2:** The window does not slide to the bottom-left corner during any state transition. The window stays in place and resizes smoothly.
- [ ] **AC-1.3:** `window.center()` is still called after the resize (to center the window when it first appears), but the animation fight is eliminated because the origin is no longer forced to `.zero` before centering.
- [ ] **AC-1.4:** The `.ready` case is not modified — it already uses the correct pattern.

### Bug 2 — Bundle path mismatch

- [ ] **AC-2.1:** `bundle-app.sh` copies `Syxx_SyxxApp.bundle` to `Syxx.app/Syxx_SyxxApp.bundle` (the app root), matching the path `Bundle.module` expects.
- [ ] **AC-2.4:** `bash bundle-app.sh` produces a working `Syxx.app` where `Bundle.module` resolves without the `buildPath` fallback.
- [ ] **AC-2.5:** The app launches without crashing when run from the produced `.app` bundle (not from the dev build directory).
- [ ] **AC-2.6:** The `resource_bundle_accessor.swift` is not modified — it is auto-generated by SwiftPM. The fix is in the copy destination.

### Cross-cutting

- [ ] **AC-3.1:** `swift build --package-path macOS` produces zero errors.
- [ ] **AC-3.2:** The EULA gate and Guided Setup render correctly after the fix (no regression).
- [ ] **AC-3.3:** The fix does not affect Windows or Linux platforms.

## Out of Scope

- Regenerating `resource_bundle_accessor.swift` (auto-generated)
- Changing the `buildPath` fallback in the generated code
- Server-side changes
- Windows or Linux modifications
- `GuidedSetup.frame(minWidth: 1050)` removal
