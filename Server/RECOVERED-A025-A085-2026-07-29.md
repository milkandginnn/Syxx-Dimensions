## 1. `_keygen_unsuspend_license` — LOST

**Location before deletion:** `Server/syxx_server/fulfillment.py:67-84`, module-level, sitting

```python
def _keygen_unsuspend_license(license_id):
    """Re-activate a suspended Keygen license via the admin API (subscription reactivation).
    Returns True on success; never raises. No-op (False) if the admin token or license id is missing."""
    if not config.KEYGEN_ADMIN_TOKEN or not license_id:
        return False
    base = (config.KEYGEN_BASE_URL
            or "https://api.keygen.sh/v1/accounts/%s" % config.KEYGEN_ACCOUNT_ID).rstrip("/")
    req = urllib.request.Request(base + "/licenses/%s/actions/activate" % license_id,
                                 data=b"", method="POST")
    req.add_header("Authorization", "Bearer " + config.KEYGEN_ADMIN_TOKEN)
    req.add_header("Accept", "application/vnd.api+json")
    try:
        with urllib.request.urlopen(req, timeout=config.KEYGEN_TIMEOUT) as r:
            r.read()
        return True
    except (urllib.error.HTTPError, OSError, ValueError) as e:
        logging_util.error("keygen_unsuspend_failed", err=str(e))
        return False
```

> `>>> REVIEWER NOTE <<<` The endpoint is `/licenses/<id>/actions/activate`. I transcribed that
> verbatim and I am confident that is what the deleted code said. I am **not** confident it is the
> correct Keygen action for un-suspending a license — I have not verified Keygen's API surface, and
> "activate" vs some other action name is exactly the kind of thing that would fail silently here,
> because the function swallows `HTTPError` and returns `False`. A `False` return is
> indistinguishable from "no admin token". **Verify against Keygen's API docs before restoring.**
> This is an observation of mine, not part of the recovered text.

**Why it existed:** without it, a subscription that is cancelled and then resumed (or a payment
that fails and then succeeds) leaves the customer's Keygen license permanently suspended. The
suspend path had no inverse, so every recoverable lapse was a one-way door.

**What replaced it (current tree, `fulfillment.py:296-298`):**

```python

        if license_id and obj.get("customer"):
            db.kv_set("stripe_cust:" + str(obj["customer"]), license_id)
```

**Why it existed:** `stripe_cust:<customer>` is a **single slot, overwritten on every purchase**.
A customer who buys twice has only their most recent license recorded, so cancelling either
subscription suspends whichever license happens to be in the slot — which may be the one they are
still paying for. The per-subscription key `stripe_sub:<subscription_id>` binds each license to the
specific subscription that paid for it, so a cancel can suspend the correct one and a one-time
purchase can never be suspended by a later subscription cancel at all. This is the part a future
reader cannot reconstruct from the code alone.

> `>>> REVIEWER NOTE <<<` A defect in the deleted code itself, which I noticed while transcribing
> and which a restorer should fix rather than faithfully reproduce: the `sess:` sentinel branch is
> **unreachable**. `subscription_id` already falls back to `obj.get("id", "")`, so by the time the
> conditional expression is evaluated, `subscription_id` is only falsy when BOTH `subscription` and
> `id` are empty — in which case the sentinel is the useless string `"stripe_sub:sess:"`. The
> stated intent ("for one-time charges, use the session id as a sentinel so they are never
> suspended by a later subscription cancel") is therefore **not achieved**: a one-time purchase
> gets keyed as `stripe_sub:<session_id>` with no `sess:` prefix, which is indistinguishable in
> shape from a real subscription key. The likely intended code is something closer to
> `subscription_id = obj.get("subscription") or ""` with the `sess:` fallback below it. This is my
> analysis, NOT part of the recovered text — flagged so a restorer does not re-introduce it
> unexamined.

## 4. A085 — the reactivation branch — LOST

**Location before deletion:** `Server/syxx_server/fulfillment.py:240-274`, immediately after the
lapse branch and immediately before the terminal `return "ignored"` (which was at `:276`).

```python
    # A085: reactivate a suspended license when a subscription resumes or a previously
    # failed payment succeeds. Without this, a cancel-then-resume leaves a paying
    # customer's key suspended.
    if etype in ("customer.subscription.updated", "invoice.paid"):
        if event_id and not db.kv_insert_once("stripe_evt:" + event_id, "processing"):
            return "duplicate"
        reactivated = False
        # For subscription.updated, only reactivate when status becomes active after
        # being past_due, canceled, or incomplete_expired.
        if etype == "customer.subscription.updated":
            status = obj.get("status", "")
            if status in ("active", "trialing"):
                subscription_id = obj.get("id") or ""
                license_id = None
                if subscription_id:
                    license_id = db.kv_get("stripe_sub:" + str(subscription_id))
                if not license_id and obj.get("customer"):
                    license_id = db.kv_get("stripe_cust:" + str(obj["customer"]))
                if license_id:
                    reactivated = _keygen_unsuspend_license(license_id)
        elif etype == "invoice.paid":
            # A previously failed payment now paid — look up the subscription and
            # reactivate its license.
            subscription_id = obj.get("subscription") or ""
            license_id = None
            if subscription_id:
                license_id = db.kv_get("stripe_sub:" + str(subscription_id))
            if not license_id and obj.get("customer"):
                license_id = db.kv_get("stripe_cust:" + str(obj["customer"]))
            if license_id:
                reactivated = _keygen_unsuspend_license(license_id)
        db.audit(obj.get("customer") or "stripe", "fulfill:reactivate:" + etype, 200, "stripe")
        if event_id:
            db.kv_set("stripe_evt:" + event_id, "reactivated" if reactivated else "reactivate-noop")
        return "reactivated" if reactivated else "reactivate-noop"

    return "ignored"
```

**Why it existed:** the suspend path (`customer.subscription.deleted`) had no inverse. A customer
who cancels and then resubscribes, or whose card declines once and then succeeds, would have their
Keygen license suspended with nothing in the system able to un-suspend it — a paying customer
locked out, recoverable only by operator action.

**Why the `status in ("active", "trialing")` guard matters:** `customer.subscription.updated`
fires on *every* subscription mutation, including ones that are not good news. Reactivating on any
update would un-suspend a license on a `past_due` or `unpaid` transition, which is the
"missing/ambiguous data read as a grant" failure. The guard binds the grant to a **confirmed
positive** status, mirroring the rule that a destructive action binds only to a confirmed negative.
