Malware attacks have become one of the most critical issues in
the Internet nowadays. Most types of malware, after infecting a
computer, attempt contacts to the Command and Control (C&C)
servers using IP addresses or Fully Qualified Domain Name (FQDN)
for further instructions. In the former case, the malware connects to
the C&C servers directly without DNS name resolutions, while in
the later case, DNS name resolutions for obtaining the IP addresses
of the C&C servers are required. In both cases, the outbound traffic
will be initialized by an unrecognized application program, the malware. In this research, we focus on these peculiarities and propose
an anomaly detection system on user terminals based on outbound
traffic filtering by using Software Defined Network (SDN) and DNS
Response Policy Zone (DNS RPZ) technologies. In the proposed
system, the outbound traffic initialized by unrecognized application
programs or destined to the IP addresses obtained without DNS
name resolutions will be detected and blocked on user terminals.
What’s more, in order to reduce false positive detections, an alert
message will make the users decide whether or not to allow the
detected traffic. We implemented a prototype system on MacOS
machine and conducted feature evaluations. According to the evaluation results, we confirmed that the proposed system worked
exactly as we designed with the features of detection, blocking and
alerting anomalies on user terminals.

INTRODUCTION

The Internet has become one of the indispensable infrastructures
for the human beings’ social activities nowadays. The numbers
of the Internet users, Internet services and Internet-connected devices keep on increasing every year. In the meanwhile, malware
attacks has been one of the most critical issues in the Internet for
years. According to the “2019 Internet Security Threat Report” from
Symantec [1], self. propagating Emotet, one of the most popular
malware, jumps up to 16% in 2018 from 4% in 2017. In addition, the
report clarified t hat MacOS malware variants also continued to
increase in 2018 which was up 80.1% from 2016 and 0.6% from 2017.
Once a computer is infected by some type of malware, not only
the victim’s credentials such as login accounts of online banking
system and credit card information can be stolen but also the victim will be forced to attend further cyber attacks such as SPAM
mail proliferation, Distributed Denial of Service (DDoS) attacks, etc.
Most types of malware attempt connections to the Command and
Control (C&C) servers in order to obtain further instructions after
infecting a computer [2–5]. The C&C servers, in general, indicate
the target IP addresses or Fully Qualified Domain Names (FQDNs)
[6] in the instructions so that the infected computer can conduct
further attacks using the IP addresses directly or after the Domain
Name System (DNS) [7] based name resolutions [8–10]. Another
focusing point is that most types of malware attempt to hide itself from the users and conforms the principle by performing the
preliminary DNS name resolutions. Therefore, DNS traffic monitoring and application program identification on user terminals
become important. DNS name resolution is one of the most widely
used Internet services for providing various mapping information
between domain names and corresponding services such as IP addresses, mail servers, etc. The preliminary DNS name resolution
is required prior to using any Internet services because almost all
Internet users do not use IP addresses directly. However, a malware
infected computer may obtain the target IP addresses from the C&C
servers directly which makes direct communication without the
preliminary DNS name resolution possible.
With considering the above background and rationales, this paper proposes an anomaly detec- tion system on user terminals

2.2

Related work

This section introduces some related work in general perspective
and those focusing on practical use of DNS. In general perspective,
the majority of existing research has been focused on centralized
solutions and real time detection by using variant technologies such
as machine learning, signature matching and anomaly detections,
etc. [11–14].
Huda et al. [11] proposed a hybrid framework by using more
than one complementary filters and a wrapper selection approach
to identify the most significant run-time behavioral characteristics of malware in order to mitigate the load of processing a large
number of run-time malware features. Homayoun et al. [12] proposed a ransomware detection system by using two deep learning
techniques Long Short-Term Memory (LSTM) and Convolutional
Neural Network (CNN) as well as a classification algorithm softmax. Villalba et al. [13] proposed an intrusion detection system
based on analysis of network traffic payload by implementing a
“dynamic pre-processor” of Snort. The system used legitimate and
malicious traffic samples in data training and created a statistical model for the legitimate network traffic using the Bloom filter
and n-grams technologies. Viegas et al. [14] proposed an approach
named BigFlow which is capable of processing high-speed network
traffic and evolved attacks based on machine learning. The BigFlow
used a verification method for checking the classifier outcome to
provide reliability but manually updated the classification model
when a suspicious packet was found.
On the other hand, several DNS based solutions have been proposed for malware detection. For example, monitoring the success
or failure of DNS name resolutions, monitoring the NS (Name
Server) records achievement history and statistical analysis on the
number of FQDNs in DNS queries in one day have been used in
the literature [15, 16]. However, these solutions consume a lot of
time for DNS traffic analysis. In addition, DNSBL [17] and DNS
Sinkhole [18] also have been known as well-used technologies for
detection and blocking the communication to the C&C servers and
malicious domain names. By using these technologies, when the
malware-infected computes access to the malicious domain names

2.1 Target threat model
The Internet communication uses IP addresses assigned to each
computer while they are not appro- priate to be remembered by human beings when using so many Internet services. As an alternative,
FQDN is used and the translating service is provided by DNS name
resolutions. Accordingly, the preliminary DNS name resolutions
are required prior to the real Internet communication such as web
browsing and email transmission, etc. Once a computer is infected
by some type of malware, in most cases the malware searches the
C&C servers for obtaining further instructions. Figure 1 shows an
example of cyber attack conducted by some type of malware. In this
example, the malware infected computer obtains the IP addresses
of the attack targets from the C&C server without the preliminary
DNS name resolutions. Consequently, the infected computer can
attack the target using the IP addresses directly without the preliminary DNS name resolutions. On the other hand, the malware which
is an unrecognized application program on the infected computer
may perform the preliminary DNS name resolutions in order to
act as legitimate communication. In both cases, the malware and

3.2.1 Domain Name Resolution Unit (DNRU). The DNRU processes
domain name resolution re- quests from the user terminals (steps
1 and 9) and registers the IP addresses included in the “answer

database with adding the IP address “192.168.0.80” in the database

3.2.2 Outbound Traffic Filtering Unit (OTFU). The OTFU monitors
all outbound traffic and deter- mines whether to allow or deny
based on the registration status of the application programs and
destination IP addresses. It also has pop-up alert feature in order
to let the user make the decisions. The process verification feature
identifies the application programs that initialize the outbound
traffic (TCP and UDP) and verifies them on the database (steps 3
and 11 on solid line). If the process been registered, the procedure
goes to the destination IP address verification stage (steps 4-1 or
12-1 on solid line) otherwise, a pop-up alert will be displayed (steps
4-2 or 12-2). If the user allowed to use the application program,
the process will be registered as legitimate (steps 4-3 or 12-3) and
the procedure goes to the destination IP address verification stage,
otherwise it will be registered as anomaly and the outbound traffic
will be dropped. The Destination IP address verification feature
verifies the destination IP addresses on the database (steps 5 and
13 on solid line). If the destination IP address has been registered,
the outbound traffic will be passed through (steps 6-1 or 14-1 on
solid line), otherwise, a pop-up alert will be displayed (steps 6-2 or
14-2 on dashed line). If the user allowed to communicate with the
IP address, it will be registered as legitimate (steps 6-3 and 14-3 on
dashed line) and the outbound traffic will be passed through (steps
7 and 15 on solid line), otherwise it will be registered as anomaly

3.1

Architecture of the proposed system

The proposed system consists of two main units, Domain Name Resolution Unit (DNRU) and Outbound Traffic Filtering Unit (OTFU).
Figure 2 illustrates the architecture of the proposed system.

Key idea of design rationale

The key idea of the design rationale for the proposed system is
DNS query monitoring and appli- cation program identification
(hereafter, process identification) on user terminals. For example,
some types of malware need to identify the IP addresses of the
C&C servers by using DNS name resolutions [19, 20] and others
directly involve DNS traffic into C&C communication by using
DNS tunneling technologies [21, 22] and DNS TXT record [10].
Therefore, the first focusing point in the idea is that the outbound
traffic without the preliminary DNS name resolutions should be
considered as anomalies. Another focusing point is that the malware
can be installed or copied on the user terminals unconsciously
and the existence can be invisible to the users. Accordingly, the
outbound traffic sent from those unrecognized processes, no matter
with or without the preliminary DNS name resolutions, should also
be considered as anomalies.

3.3

Temporarily block SYN packet

In the proposed system, the suspicious TCP connection will be
hold on for a while waiting for the decision from the users. Thus,
when an alert message is displayed for the users to decide whether
allow the detected TCP connection or not, the users need to make
a decision within the SYN timeout configured in the operating
system or the specific application. In case of that the users make
decision after the TCP connection has been timed out, even if
the users allows the TCP connection the communication will fail.
Accordingly, a longer TCP SYN establish timeout is required in
order to practically use the proposed system. According to our
investigations, in MacOS operating system, the default value of
“net.inet.tcp.keepinit” is 75 seconds indicating the timeout for establishing SYN and “net.inet.tcp.broken_peer_syn_rexmit_thres”
is 10 indicating the number of SYN retransmission time before
TCP connection fails. Accordingly, the users technically can obtain
12.5 minutes for deciding whether allow the outbound traffic that
triggers the alert message.

IMPLEMENTATION AND EVALUATION

A prototype system has been implemented on a MacOS host machine using SDN [23]and VirtualBox [24] technologies. In the previous work [8], a lightwitht prototype system for only TCP protocol
has been implemented on a Windows7 operating system using Cygwin [25] and “WinDivert” library [26]. However, MacOS does not
support “Divert” functionality and the Windows7-base prototype
system had a low-performance issue due to the usage of text basis
destination IP address and application program whitelists. In this
paper, we extend the implementation to MacOS machine and also
solve the issues occurred in the previous Windows7-base prototype
by using SDN and virtualization technologies.

CONCLUSION

In this paper, we proposed an anomaly detection system on user
terminals based on outbound traffic filtering by DNS traffic monitoring and application program identification. In the proposed system,
DNS RPZ is introduced for managing registered application programs and DNS-resolved IP addresses and OpenFlow based SDN is
used for network traffic control. With effective control on outbound
network traffic and light weight query-response for white and black
lists inquiries, the proposed system realized a user terminal based
anomaly detection solution for both of TCP and UDP protocols.
More importantly, the user can make decision (allow or deny) based
on the alert message for detected outbound traffic so that the false
positive rate of blocking can be reduced. The prototype system
presented in this paper was implemented on a MacOS machine and
it is also possible to be deployed on a Windows system. For the
future work, implementation for Windows system and performance
evaluation are on the top priority and the deployment on a real
network is also considered.
