Cage capture-output pane — platform faux-terminal spec

Design source-of-truth comparison. The live streaming faux-terminal feed currently exists on macOS only. This spec preserves the unix look on macOS/Ubuntu and defines a PowerShell-native rendering for Windows so the pane is not ported verbatim when parity work lands.

Finding. The owner's literal suspicion is refuted as stated: the unix-styled faux terminal has not been copied to Windows — Windows has no live-feed terminal pane at all (a parity gap). The real risk is latent: the Windows XAML is written "for parity with macOS", so a future port would carry the zsh prompt, sudo, and • bullets across unless this spec pre-empts it.

Windows — proposedPowerShell-native

PS C:\> syxx cage --duration 30
Listening for DNS on port 53…
[14:03:19]  example.com  via chrome.exe  (1.1.1.1)
[14:03:21]  telemetry.acme.io  via svchost.exe  (8.8.8.8)
[14:03:22]  cdn.example.net  via chrome.exe  (1.1.1.1)

Cascadia Mono (already the token). No unix carry-over: PowerShell PS C:\> prompt, no sudo (elevation is UAC), bracketed [HH:mm:ss] instead of the • bullet, .exe on process names. Dark violet surface harmonized with the app theme — not raw PowerShell console blue.

Why the app violet theme, not classic PowerShell blue

PowerShell 5.1's console is #012456 dark blue with white/yellow/cyan text. Importing that raw would clash with Syxx's violet-gold system and fracture brand cohesion. Modern Windows Terminal already defaults to a dark, near-black surface with a colored prompt — which the app's own #100826 / #0b0518 canvas matches far more closely. Recommendation: harmonize with existing tokens, borrow only PowerShell's conventions (prompt string, no bullets, .exe), not its palette.
