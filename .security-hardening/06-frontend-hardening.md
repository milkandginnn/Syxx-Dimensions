## Assessment

The Syxx web frontend is a **static HTML mockup** with inline `onclick` handlers. It does not:
- Render user-controlled content
- Accept user input beyond navigation
- Perform client-side data processing
- Communicate with the server API (the mockup is not wired to the backend)

The production web surface at syxx.app consists of:
- Static marketing pages
- The `/api/whats-new` endpoint (server-rendered HTML with strict CSP)
- The DNS leak test page at leaktest.syxx.app (JavaScript that calls `/api/leak/start` and `/api/leak/check`)

### Security Controls Already in Place

| Control | Status | Notes |
|---|---|---|
| CSP | ✅ | Strict CSP on `/api/whats-new`; global CSP on API responses |
| HSTS | ✅ | Emitted when TLS detected |
| X-Frame-Options | ✅ | DENY — prevents clickjacking |
| X-Content-Type-Options | ✅ | nosniff |
| Referrer-Policy | ✅ | no-referrer |
| Permissions-Policy | ✅ | Camera, mic, geolocation, interest-cohort disabled |

### Recommendations (When Frontend Goes Dynamic)

When the web frontend is de-mocked and connected to real API endpoints (per the web features implementation roadmap), the following should be implemented:

1. **CSP nonce** — Add per-request nonces to any server-rendered HTML that includes inline scripts
2. **Subresource Integrity (SRI)** — Add `integrity` attributes to all external `<script>` and `<link>` tags
3. **PKCE OAuth2** — If browser-based authentication is added, use PKCE flow for the authorization code grant
4. **Secure cookies** — If sessions are introduced, use `SameSite=Strict; HttpOnly; Secure` flags
5. **DOMPurify** — If any user-controlled content is rendered, sanitize with DOMPurify before insertion

These are not needed today because the frontend is static and carries no dynamic content.
