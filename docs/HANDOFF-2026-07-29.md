## 4. Findings that outrank the remaining plan work

Ordered by risk. Items 1 and 2 are consumer-protection exposure, not code quality.

1. **`Server/index.html:517` publishes a false privacy claim.** It says "Nothing is sent back
   except an anonymous usage report with no identifying details, which you can turn off." This
   contradicts `Server/privacy.html:60-67`, which correctly discloses that license keys go to the
   licensing service and that the leak test works by the server observing your resolver's IP.
   A published understatement of processing is the kind of statement the FTC and EU consumer
   authorities act on. **Highest-risk single string on the site.**

2. **No auto-renewal disclosure at the point of purchase.** `index.html:276-307` is the checkout
   page and never says the subscription renews automatically and charges again. California
   B&P §17601 requires the auto-renewal terms in *visual proximity* to the consent request; a
   separate Terms page does not satisfy that. §17602(d)(1) also requires online cancellation for
   online signups, and there is no billing portal endpoint. EU CRD Art 8(2) applies too.

3. **Telemetry consent defaults to ON, which defeats an otherwise correct design.**
   `SyxxSettings.swift:36` and `SyxxSettings.cs:30-31` both default `telemetryEnabled = true`, and
   `DimensionService.swift:51` fires unless `dimension_opt_out` was set (absent on first run).
   The `TelemetryGate` itself is genuinely well built: tri-state, `unknown` is not consent, and a
   corrupt settings file fails closed. The bug is upstream — on a real first run the file is
   absent, `.default` returns `true`, and `currentConsent()` returns granted for a user never
   asked. Fix is a two-line twin change (macOS + Windows + Avalonia settings path in one pass).

4. **Google Fonts hotlinked from every page** (`privacy.html:11-13`, `index.html:28-29`, and the
   two new legal pages). Every EU visitor's IP goes to Google LLC with no consent. This is the
   exact pattern behind Munich Regional Court Az. 3 O 17493/20. Fix: self-host, site-wide, one pass.

5. **Three different EULAs ship today.** `EULAPanel.swift:82-110` (8 sections, no device limit),
   `LicenseView.xaml.cs:170-180` (9 sections), `index.html:512-523` (10 sections, promises **five
   devices**). Keygen enforces no machine binding at all today, so the website promise is
   unenforced. macOS has a real EULA gate but its `GuidedSetup.swift:34-47` accept path bypasses
   the checkbox. **Windows shows the EULA but never records acceptance. Linux has no EULA at all,
   and Linux ships first.**

6. **Undisclosed processing:** trial device fingerprint (`app.py:1141-1149`, `db.py:967-978`,
   retained **365 days**) appears nowhere in the privacy policy; audit-log IPs (`app.py:1122-1204`,
   7 days) are described only as "server logs rotate on a fixed schedule".

7. **New §5 violations in `index.html` not previously filed:** the Warp panel (`:186-193`) renders
   "2 differences found…" beside hardcoded source panes (`:467-505`) and hardcoded IPs (`:176`,
   `:181`) with no request ever made and no "demo" label, while the terminal right below it *does*
   label itself demo at `:435-437`. The Manage panel (`:337,343,349`) prints a plan price, a
   `Visa •••• 4242`, and a license key synthesised from an FNV hash of the email (`:624`).
