# Stage-5 validator honesty gaps — ENGINE LANE (for syxx-neural-executor)

**Source:** CX-1..3 surfacing adversarial honesty audit, 2026-07-12. **Verified against code**, not just asserted.

The GUI surface gates ALL green/clean rendering on `Stage5Presentation.isValid` (== `validationErrors().isEmpty`). Four gaps let a reassuring surface through that gate. Fix in `validationErrors()` (`macOS/Sources/SyxxKit/Synthesis/Stage5Presentation.swift`) and the `ValidationErrors()` C# twin (`Windows/Syxx.Kit/Synthesis/Stage5Presentation.cs`), with **negative golden fixtures + byte-parity**. Hardening `isValid` closes all four **at the source** — the surface already gates on it, so no surface change is needed for these four.

- **V1 — schemaVersion not fail-closed (HIGH, NEW).** `validationErrors()` never checks `schemaVersion`. The `schemaVersion==1` guard lives only in the standalone `decode(_:)` (`Stage5Presentation.swift:366`), which the `Conclusion` Codable path BYPASSES (`Conclusion.swift:~84` decodes `stage5` via `decodeIfPresent`, using the synthesized initializer). A persisted/received `schemaVersion=2` object therefore passes `isValid` and renders as a trusted determination. **Fix:** `if schemaVersion != 1 { errs.append("unsupported schemaVersion \(schemaVersion)") }`. NB: the P1.0 (`bcf817e`) commit message claimed "unsupported schemaVersion fails closed" — that is true only on the `decode(_:)` path, not the live Conclusion path. This corrects the record.
- **V2 — clean not blocked by critical missing data (HIGH; = P1.2/P1.3, extend to the DTO validator).** The clean-state block (`Stage5Presentation.swift:457`) never inspects `completeness.criticalAvailable/criticalExpected`. A `state==.clean` object with `criticalAvailable < criticalExpected` and no hardGate passes `isValid` → green "No tampering detected". §13 rule 9: clean is impossible with critical missing data. **Fix:** reject clean when `cc.criticalAvailable < cc.criticalExpected`.
- **V3 — clean not required finding/inferred-free (HIGH; = P1.5 `.positive`-blocks-clean, extend to the DTO validator).** Clean-state does not require `findings` empty or `provenance.inferred` free of tamper-class. Green "No tampering detected" can render above ranked tamper findings + inferred "The address you were given was changed". **Fix:** reject clean when `findings` is non-empty or any inferred/finding is tamper-class.
- **V4 — clean not blocked by active conflict/uncertainty (MEDIUM).** Clean-state does not reject when `honesty.conflict`/`honesty.uncertainty` are present. A green verdict can sit above "The evidence genuinely disagrees (50%)". **Fix:** reject clean when a conflict/uncertainty signal is present above the display threshold.

**Lane note:** V2 and V3 are the same invariants as the executor's planned P1.2/P1.3 (critical-forbids-clean) and P1.5 (`.positive`-blocks-clean) — this just extends them to the `Stage5Presentation` DTO validator, not only the `SynthesisEngine` verdict path. V1 is a new DTO-contract fix. The surface-side gaps (green agreement chips, mac/Win casing, dead `ReasoningPresentation`, copy-gate labels) are handled separately in the GUI lane — NOT here.
