# Specification: Complete macOS GUI — SwiftUI View Parity

**Track ID:** gui-complete-macos_20260805
**Type:** Feature
**Created:** 2026-08-05
**Status:** Draft

## Summary

Build all 10 missing tool views in the macOS SwiftUI target to achieve visual and behavioral parity with the existing Windows (WinUI 3) and Linux (Avalonia) GUIs. The macOS app currently has only 4 shared components but is missing every tool view that users interact with.

## Context

Syxx ships three desktop GUIs from two shared-logic twins. Windows (14 views) and Linux (13 views) both have complete tool view sets. macOS has the design system (`IoDesignSystem.swift`), scroll container (`PurpleScrollView.swift`), logo (`LogoView.swift`), and result display (`OverallResultView.swift`) — but none of the actual tool views that present investigation results to users.

The macOS `ContentView.swift` already has the `NavigationSplitView` sidebar and window chrome (`WindowChromeConfigurator`), but the detail pane has no tool views to navigate to.

## Acceptance Criteria

- [ ] All 10 core tool views implemented in SwiftUI (Dashboard, Prophet, Glutton, Mirror, Portal, Witness, Cage, Conclusions, FirstRun, License)
- [ ] Each view matches the layout hierarchy and visual design of its WinUI 3 counterpart (sidebar navigation, card-based sections, design token colors)
- [ ] `NavigationSplitView` sidebar routes to each tool view correctly
- [ ] ViewModels created for each view, binding to `SyxxKit` for data
- [ ] Dark/light mode support via `@Environment(\.colorScheme)` and `IoDesignSystem` tokens
- [ ] Accessibility: all controls labeled, keyboard navigation working, Dynamic Type support
- [ ] `swift build` succeeds with zero errors under Swift 6 strict concurrency
- [ ] `bundle-app.sh` produces a working `Syxx.app` with all views navigable

## Dependencies

- `SyxxKit` (Swift shared-logic twin) — provides data models, investigation engine, synthesis engine
- `IoDesignSystem.swift` — provides color tokens, font stacks, spacing constants
- `ContentView.swift` — existing `NavigationSplitView` and window chrome

## Out of Scope

- Server-side changes (Python `syxx_server/`)
- Windows or Linux view modifications
- New investigation features or engine logic
- Cage feed UI (rejected — "Listening for DNS on port 53…" placeholder not needed)
- Qt target (not a current Syxx platform)
- App Store submission or notarization
- Settings/Preferences view (separate track)

## Technical Notes

- Swift 6 strict concurrency: all view code `@MainActor`, data types `Sendable`, static caches `nonisolated(unsafe)`
- `ContentView` owns edge margins (`.padding(35)`) — individual views own internal spacing only
- DashboardView is the exception: wrapped in `GeometryReader` for scroll anchoring
- Build command: `swift build --package-path macOS && bash macOS/bundle-app.sh`
- Use `GUI-developer` agent for implementation
